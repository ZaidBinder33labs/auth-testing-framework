# auth-testing-framework

**Multi-tenant authentication + Redis testing framework.**

Built as a Node.js monorepo of packages plus a shared test tree. A target
application (e.g. Binder) is integrated through adapters only — the cores never
see target-specific schema.

## What "application-agnostic" means here, precisely

A **target descriptor** (`config/targets/<name>.json`) can cover any application
that authenticates with a single credential pair, issues one access token,
refreshes it with one call, and ends the session with one call — varying only the
endpoint paths, the token/refresh/expiry field names, whether the refresh token
rides in an HttpOnly cookie or a JSON body, whether rotation is on, what a
successful logout returns, the JWT claim names, and the Redis key prefixes.

An application outside that shape — a two-step or challenge-response login, an
OAuth/OIDC redirect, a refresh token carried in a request header rather than a
cookie or body, or an authorization scheme other than `Authorization: Bearer` —
needs a new adapter class. The descriptor does not, and cannot, describe the
*flow*; only its vocabulary. That boundary is a deliberate choice for now: with
one real target, a flow abstraction would be designed against a sample size of
one. It is recorded as a future option, not built.

`config/targets/example.json` is a worked target that shares nothing with the
Binder descriptor, and `packages/adapters/tests/example-target.spec.js` drives the
same adapter through it. That test is the evidence for this claim; without it the
claim would be untested.

## Packages

| Package | Responsibility |
|---|---|
| `@atf/tenant-core` | Tenant/actor identity, registry, validation |
| `@atf/auth-core` | AuthManager: login/refresh/logout/session lifecycle |
| `@atf/redis-observer` | Read-only Redis observation, TTL, fingerprints |
| `@atf/state-diff` | Snapshot diff engine |
| `@atf/isolation-engine` | Tenant/session isolation validation |
| `@atf/token-security` | Fingerprinting, redaction, JWT/opaque inspection |
| `@atf/concurrency-engine` | RefreshLock, parallelLimit, waitForRace |
| `@atf/test-fixtures` | Deterministic tenants/actors (A/B/C, A1..C1) |
| `@atf/reporting` | Evidence, safe serialization, Reporter |
| `@atf/adapters` | Adapter contracts + MockAuth/MockTenant/MockRedis |
| `@atf/lifecycle-engine` | BEFORE/AFTER scenario engine |
| `@atf/http-transport` | Application-agnostic HTTP transport, cookie-keeping request context |
| `@atf/target-config` | Target descriptors: paths, field names, prefixes, logout semantics |

## Testing lifecycle

```
BEFORE SNAPSHOT → AUTH ACTION → WAIT FOR EXPECTED STATE → AFTER SNAPSHOT
→ REDIS DIFF → TENANT ISOLATION → AUTH INVARIANTS → SAFE REPORT
```

## Test tree

```
tests/
├── unit/  authentication/  session/  token/  redis/  tenancy/
├── security/  concurrency/  lifecycle/  contract/  integration/  selftest/
```

## Redis modes

- `MOCK_REDIS` (default for self-tests) — in-memory mock.
- `READ_ONLY` (default for external targets) — mutations blocked.
- `DEDICATED_TEST_REDIS` / `TEST_NAMESPACE` — controlled mutation.

`FLUSHALL`/`FLUSHDB`/wildcard deletes are never used.

## Quick start

```bash
npm install
npm run test:all
```

## Commands

```bash
npm run test:unit         # package unit tests
npm run test:contract     # adapter contracts
npm run test:integration  # end-to-end scenarios
npm run test:security     # security suite
npm run test:redis        # redis suite
npm run test:tenancy      # isolation suite
npm run test:concurrency  # concurrency suite
npm run test:self         # framework self-tests
npm run test:all          # everything
```
